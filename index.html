Principles of Network Applications

💡
Network apps run on end systems (not on network-core devices like routers). This allows rapid development and deployment without changing the underlying network infrastructure.
🖥️

What is a Network App?

  • Programs running on different end systems
  • Communicate with each other over the network
  • e.g., web browser ↔ web server
  • No software needed for routers/switches
📋

Application-Layer Protocol Defines:

  • Types of messages (request, response)
  • Syntax: fields & how they're delineated
  • Semantics: meaning of information
  • Rules for when/how to send messages
🔓

Open vs Proprietary Protocols

  • Open: defined in RFCs (HTTP, SMTP, DNS)
  • Anyone can implement; ensures interoperability
  • Proprietary: e.g., Skype, Zoom
  • Closed design, vendor controls

03

Transport Services

Apps need different things from the network. The four key dimensions are:

✅

Data Integrity

File transfer & web transactions need 100% reliable delivery. Audio streaming can tolerate some loss.

⏱️

Timing

VoIP and interactive games need low delay (10s of ms) to be usable. File download doesn't care.

📊

Throughput

Multimedia needs a minimum guaranteed rate. "Elastic" apps (email) use whatever they get.

🔒

Security

Encryption, data integrity verification, and endpoint authentication.

TCP vs UDP — Choose Your Protocol

What TCP Provides ✓

  • Reliable transport — no data lost
  • Flow control (won't overwhelm receiver)
  • Congestion control (throttles on overload)
  • Connection-oriented (handshake setup)
  • In-order delivery

What TCP Does NOT Provide ✗

  • Timing guarantees
  • Minimum throughput guarantee
  • Security (need TLS on top)

Apps using TCP: HTTP, FTP, SMTP, streaming audio/video

What UDP Provides

  • Lightweight, connectionless
  • No handshake — just send
  • Lower overhead than TCP

What UDP Does NOT Provide ✗

  • No reliability
  • No flow control
  • No congestion control
  • No security, no ordering
❓
Why use UDP? Speed and simplicity. For real-time apps like DNS lookups, VoIP, or video streaming, the overhead of TCP handshaking is too costly. A lost packet is better than a delayed one.

🔒 Securing TCP with TLS

Vanilla TCP has no encryption. Transport Layer Security (TLS) is implemented in the application layer on top of TCP, providing encrypted connections, data integrity, and endpoint authentication.

Web and HTTP

🌐
HTTP (HyperText Transfer Protocol) is the Web's application-layer protocol. It follows a client/server model and runs over TCP (port 80). Critically, HTTP is stateless — the server keeps no memory of past requests.

⏱️ Non-Persistent HTTP Response Time = 2RTT + File Transmission

RTT = Round-Trip Time (time for a packet to travel client → server → client)

Non-Persistent HTTP (one object)
RTT 1 – TCP setup
RTT 2 – HTTP request
File transmission

✅
Persistent HTTP (HTTP 1.1) keeps the connection open after sending — subsequent objects only need 1 RTT each, roughly cutting response time in half.

The status line gives: protocol + status code + phrase. Then headers. Then the body (the actual content).

GET

Retrieve a resource. Can pass data via URL: ?key=value

POST

Send data in the message body (e.g. form submissions).

HEAD

Like GET but server returns headers only — no body. Useful for checking if a file exists.

PUT

Upload/replace a file at a specified URL on the server.

Maintaining State: Cookies

🍪
HTTP is stateless, but sites need to remember users. Cookies solve this by storing a unique ID in the browser, linked to a server-side database record.

There are 4 components to the cookie system. Click each to learn about it:

1

Cookie header in HTTP response

Server sends Set-Cookie: 1678 when it first sees a user

2

Cookie header in HTTP request

On every future visit, browser sends Cookie: 1678

3

Cookie file on user's host

Browser manages a local file mapping domains → cookie values

4

Back-end database

Server stores user data linked to the cookie ID (cart, prefs, session)

🔍
Privacy concern: Third-party tracking cookies can follow you across multiple websites by embedding the same cookie from a shared domain (e.g., an ad network), building a profile of your browsing habits.

⚡ DNS Caching

  • Name servers cache mappings (with TTL)
  • TLD servers typically cached locally → root rarely visited
  • Cached entries can be stale if IP changes
  • Update standard: RFC 2136

🛡️ DNS Security Threats

  • DDoS: bombard root/TLD servers
  • Man-in-middle: intercept queries
  • DNS poisoning: fake replies cached
  • DNSSEC (RFC 4033) counters these

Socket Programming

🔌
A socket is the API between the application and the transport layer. You write to/read from sockets like files. There are two types: UDP sockets (connectionless datagrams) and TCP sockets (reliable byte streams).
UDP Client
from socket import *

serverName = 'hostname'
serverPort = 12000

# Create UDP socket
clientSocket = socket(
  AF_INET, SOCK_DGRAM)

msg = input('Enter sentence:')

# Attach destination & send
clientSocket.sendto(
  msg.encode(),
  (serverName, serverPort))

reply, addr = clientSocket.recvfrom(2048)
print(reply.decode())
clientSocket.close()
UDP Server
from socket import *

serverPort = 12000
serverSocket = socket(
  AF_INET, SOCK_DGRAM)

# Bind to port
serverSocket.bind(('', serverPort))
print("Ready to receive")

while True:
  msg, addr = serverSocket.recvfrom(2048)
  modified = msg.decode().upper()
  serverSocket.sendto(
    modified.encode(), addr)
TCP Client
from socket import *

serverName = 'servername'
serverPort = 12000

# SOCK_STREAM = TCP
clientSocket = socket(
  AF_INET, SOCK_STREAM)

# TCP handshake happens here!
clientSocket.connect(
  (serverName, serverPort))

msg = input('Enter sentence:')
clientSocket.send(msg.encode())

reply = clientSocket.recv(1024)
print(reply.decode())
clientSocket.close()
TCP Server
from socket import *

serverPort = 12000
# Welcoming socket
serverSocket = socket(
  AF_INET, SOCK_STREAM)
serverSocket.bind(('', serverPort))
serverSocket.listen(1)

while True:
  # New socket per client!
  connSock, addr = serverSocket.accept()
  sentence = connSock.recv(1024).decode()
  cap = sentence.upper()
  connSock.send(cap.encode())
  connSock.close() # close this conn
